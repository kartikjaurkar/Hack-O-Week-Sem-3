Hooks & React Router

Study notes covering useRef, useMemo, useCallback, useContext, custom hooks, and React Router v6+ (routes, nested routes, params, navigation).

useRef

persist a value without re-rendering

Purpose

Returns a mutable object { current: ... } that stays the same across renders. Changing .current does not trigger a re-render.

Basic usage

import { useRef, useEffect } from "react";

function SearchBox() {
  const inputRef = useRef(null);      // 1. DOM reference
  const renders = useRef(0);          // 2. mutable value

  useEffect(() => { inputRef.current.focus(); }, []);
  renders.current += 1;

  return <input ref={inputRef} placeholder="Search..." />;
}
Use cases: focusing inputs, scrolling to elements, storing timer/interval IDs, keeping the previous value of a prop/state, tracking "is mounted" flags.
Remember: don't read or write ref.current during rendering for values shown in the UI. Use state for that.

useMemo

cache a computed value

Purpose

Remembers the result of an expensive calculation and only recomputes it when a dependency changes.

Basic usage

import { useMemo, useState } from "react";

function ProductList({ products }) {
  const [query, setQuery] = useState("");

  const visible = useMemo(() => {
    return products.filter(p =>
      p.name.toLowerCase().includes(query.toLowerCase()));
  }, [products, query]);          // recompute only when these change

  return (<>
    <input value={query} onChange={e => setQuery(e.target.value)} />
    {visible.map(p => <li key={p.id}>{p.name}</li>)}
  </>);
}
Use cases: heavy filtering/sorting, derived data from large lists, keeping an object/array reference stable so a memoized child (React.memo) or an effect dependency doesn't change every render.
Remember: it's a performance hint, not a guarantee. Don't wrap cheap calculations. Measure first.

useCallback

cache a function

Purpose

Returns the same function instance between renders unless dependencies change. useCallback(fn, deps) is equivalent to useMemo(() => fn, deps).

Basic usage

import { useCallback, useState, memo } from "react";

const Row = memo(function Row({ item, onDelete }) {
  console.log("render", item.id);
  return <li onClick={() => onDelete(item.id)}>{item.text}</li>;
});

function List() {
  const [items, setItems] = useState([{ id: 1, text: "A" }, { id: 2, text: "B" }]);

  const handleDelete = useCallback(id => {
    setItems(prev => prev.filter(i => i.id !== id));  // functional update: no stale deps
  }, []);

  return <ul>{items.map(i => <Row key={i.id} item={i} onDelete={handleDelete} />)}</ul>;
}
Use cases: passing callbacks to React.memo children, functions used in useEffect dependency arrays, callbacks given to custom hooks.
useMemo vs useCallback: useMemo caches a value; useCallback caches a function. Without memo on the child, useCallback gives no benefit.

useContext

share data without prop drilling

Purpose

Reads the value of a Context from the nearest matching Provider above in the tree, so deeply nested components get data without passing props through every level.

Basic usage

import { createContext, useContext, useState } from "react";

const ThemeContext = createContext("light");          // 1. create

function ThemeProvider({ children }) {                // 2. provide
  const [theme, setTheme] = useState("light");
  const value = useMemo(() => ({ theme, setTheme }), [theme]);
  return <ThemeContext.Provider value={value}>{children}</ThemeContext.Provider>;
}

function ThemeButton() {                              // 3. consume
  const { theme, setTheme } = useContext(ThemeContext);
  return <button onClick={() => setTheme(theme === "light" ? "dark" : "light")}>{theme}</button>;
}
Use cases: theme, logged-in user, language/locale, shopping cart, app settings.
Remember: every consumer re-renders when the Provider's value changes, so memoize the value object. Context is for low-frequency, app-wide data, not for rapidly changing state.

Custom Hooks

reuse stateful logic

Purpose

A custom hook is a function whose name starts with use and that calls other hooks. It lets you extract and reuse logic (not UI) between components. Each call gets its own independent state.

Example 1: useLocalStorage

function useLocalStorage(key, initial) {
  const [value, setValue] = useState(() => {
    const saved = localStorage.getItem(key);
    return saved ? JSON.parse(saved) : initial;
  });
  useEffect(() => {
    localStorage.setItem(key, JSON.stringify(value));
  }, [key, value]);
  return [value, setValue];
}

// usage
const [name, setName] = useLocalStorage("name", "");

Example 2: useFetch

function useFetch(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    let cancelled = false;
    setLoading(true);
    fetch(url)
      .then(r => r.json())
      .then(d => !cancelled && setData(d))
      .catch(e => !cancelled && setError(e))
      .finally(() => !cancelled && setLoading(false));
    return () => { cancelled = true; };
  }, [url]);

  return { data, loading, error };
}

Example 3: wrapping useContext

function useTheme() {
  const ctx = useContext(ThemeContext);
  if (!ctx) throw new Error("useTheme must be used inside ThemeProvider");
  return ctx;
}
Rules: call hooks only at the top level (no loops, conditions, or nested functions) and only from components or other hooks. Name must start with use.

Routing & Routes

react-router-dom

Purpose

React Router maps URLs to components in a single-page app without full page reloads. Install with npm i react-router-dom.

Basic setup

// main.jsx
import { BrowserRouter } from "react-router-dom";
root.render(<BrowserRouter><App /></BrowserRouter>);

// App.jsx
import { Routes, Route, Link } from "react-router-dom";

function App() {
  return (<>
    <nav>
      <Link to="/">Home</Link>
      <Link to="/about">About</Link>
    </nav>
    <Routes>
      <Route path="/" element={<Home />} />
      <Route path="/about" element={<About />} />
      <Route path="*" element={<NotFound />} />   {/* catch-all 404 */}
    </Routes>
  </>);
}
PieceRole
BrowserRouterEnables routing using the browser History API
Routes / RouteMatch the current URL to an element
Link / NavLinkClient-side navigation links; NavLink adds an active class
path="*"Fallback for unmatched URLs

Nested Routes

Outlet

Purpose

Child routes render inside a parent's layout. The parent places an <Outlet /> where the matched child should appear. The URL structure mirrors the UI structure.

<Routes>
  <Route path="/" element={<Layout />}>
    <Route index element={<Home />} />                {/* "/" */}
    <Route path="dashboard" element={<Dashboard />}>
      <Route index element={<Overview />} />         {/* "/dashboard" */}
      <Route path="settings" element={<Settings />} />{/* "/dashboard/settings" */}
    </Route>
  </Route>
</Routes>

import { Outlet } from "react-router-dom";
function Dashboard() {
  return (<div>
    <h2>Dashboard</h2>
    <Outlet />   {/* child route renders here */}
  </div>);
}
Use cases: shared layouts (navbar + footer), dashboards with tabs/sidebars, admin sections. index routes are the default child shown at the parent's path.

Route Params

useParams · useSearchParams

Purpose

Dynamic segments (prefixed with :) capture parts of the URL, such as an ID.

<Route path="/users/:userId" element={<UserProfile />} />

import { useParams, useSearchParams } from "react-router-dom";

function UserProfile() {
  const { userId } = useParams();               // "/users/42" -> "42" (always a string)
  const [sp, setSp] = useSearchParams();        // "/users/42?tab=posts"
  const tab = sp.get("tab") ?? "info";

  return (<>
    <h2>User {userId}</h2>
    <button onClick={() => setSp({ tab: "posts" })}>Posts</button>
  </>);
}
Remember: params are strings. Convert with Number(userId) when needed. Use params for identity (/products/7) and query strings for filters (?sort=price).

Navigation

Link · NavLink · useNavigate · Navigate 
import { Link, NavLink, useNavigate, Navigate, useLocation } from "react-router-dom";

// 1. Declarative links
<Link to="/about">About</Link>
<NavLink to="/dashboard" className={({ isActive }) => isActive ? "active" : ""}>Dashboard</NavLink>

// 2. Programmatic navigation (after a form submit, login, etc.)
function LoginForm() {
  const navigate = useNavigate();
  const onSubmit = async () => {
    await login();
    navigate("/dashboard", { replace: true });   // replace = no back-button to login
  };
  // navigate(-1) goes back, navigate(1) goes forward
}

// 3. Redirect during render (e.g. protected route)
function Protected({ user, children }) {
  return user ? children : <Navigate to="/login" replace />;
}

// 4. Pass and read state
navigate("/checkout", { state: { from: "cart" } });
const { state } = useLocation();   // state.from

How Routing Works

  • The router listens to URL changes through the browser History API (pushState) and never reloads the page.
  • Routes compares the current location against each Route path (ranking the best match), then renders the matching element tree.
  • Nested routes render through Outlet, so a parent layout stays mounted while children swap.
  • Link prevents the default anchor reload and calls navigate internally.

Self-check questions

1. Why doesn't changing ref.current cause a re-render?

A ref is a plain object stored outside React's state system. React doesn't track mutations to it.

2. When is useCallback actually useful?

When the function is passed to a React.memo child or used as a dependency of another hook, so a stable identity avoids unnecessary work.

3. How does an Outlet relate to nested routes?

It marks where the parent layout renders the currently matched child route.

4. What type is a value from useParams?

Always a string (or undefined), so convert it if you need a number.

5. What must a custom hook's name start with, and why?

use, so React and linters can enforce the rules of hooks.
